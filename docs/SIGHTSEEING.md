# 東京観光スポットの追加・変更

観光案内の内容は **`src/data/i/sightseeing.json` または `src/data/k/sightseeing.json` だけで編集**できます。画面のReactコードや翻訳辞書を変更する必要はありません。エリア、説明、アクセス、滞在目安、費用、リンク、地図の位置をここから読み込みます。

## GitHubから編集する

1. リポジトリで `src/data/i/sightseeing.json`（または `k`）を開き、鉛筆ボタンで編集します。
2. 既存のスポットを書き換えるか、`spots` 配列の末尾にスポットを追加します。
3. `main` にコミットすると、既存のGitHub Actionsがビルド・公開します。
4. Actionsの成功を確認します。PWAで旧内容が出る場合は、設定画面の「キャッシュ・更新を確認」→「更新を適用」を押します。

ローカルで編集する場合は `npm run build` で確認し、変更した**ソースファイル**をGitHubへ登録してください。自動ビルドでは `dist` を手動更新する必要はありません。

## スポットを追加する

`spots` 配列内の既存の1件を複製して、次の項目を変更してください。配列の各項目の間にはカンマが必要です。JSONではコメントと末尾の余分なカンマは使えません。

```json
{
  "id": "new-place",
  "areaId": "tokyo",
  "enabled": true,
  "name": { "ja": "新しい観光地", "en": "New place" },
  "description": { "ja": "ここで何を楽しめるか。", "en": "What to see and do here." },
  "access": { "ja": "最寄り駅・出口・行き方。", "en": "Nearest station, exit and access." },
  "cost": { "ja": "料金は公式サイトで確認", "en": "Check official prices" },
  "duration": { "ja": "30〜60分", "en": "30–60 min" },
  "note": { "ja": "訪問前に確認すること。", "en": "Things to check before visiting." },
  "latitude": 35.68124,
  "longitude": 139.76499,
  "website": "https://example.com/",
  "sourceUrl": "https://example.com/access/"
}
```

この例の座標は東京駅付近の仮値です。**追加する観光地の座標と実際の公式URLに置き換えてください。**

| 項目 | 編集のポイント |
| --- | --- |
| `id` | 半角英数・ハイフンなどの重複しない名前。表示名ではありません。 |
| `areaId` | `tokyo`（東京駅）、`shinagawa`（品川）、`asakusa`（浅草・押上）、`harajuku`（原宿）、`tsukiji`（築地）、`akihabara`（秋葉原）、`shiba`（芝・東京タワー）。新エリアも追加できます。 |
| `enabled` | `false` にすると、データを残したまま非表示にできます。 |
| `name` / `description` | 観光地名と紹介文。 |
| `access` | 最寄り駅からのアクセス。乗換・出口の違いも必要なら記載します。 |
| `duration` | 滞在時間の提案。移動時間を含めず、実際の空き時間に合わせて判断します。 |
| `cost` / `note` | 費用・予約・営業時間・注意点。確定していない内容は断定しません。 |
| `latitude` / `longitude` | 緯度 / 経度。引用符なしの数値。地図のピンと経路リンクに使います。 |
| `website` | 公式サイトへのリンク。`https://`から始まるURL。 |
| `sourceUrl` | 説明やアクセスを確認した公式情報のURL。 |

並び順は `spots` 配列の順番です。スポット数は自動集計されます。日本語と英語は各項目の `ja` / `en` で編集します。英訳がまだない場合は `en` を省略でき、その項目は日本語で表示されます。

## 座標を調べる

OpenStreetMapで訪問場所を検索し、地図上の位置を右クリックして「住所を表示」などから緯度・経度を確認します。Googleマップでも地図上を右クリックすると座標が表示されます。入力順は **緯度 → 経度** です。広い公園なら、歩いて行きたい入口や川沿いの地点を選び、その旨を `note` に書くと分かりやすくなります。

## 新しいエリアを追加する

`areas` 配列へ次のような項目を追加し、スポットの `areaId` に同じ `id` を指定します。フィルターボタンも自動で追加されます。

```json
{
  "id": "ueno",
  "name": { "ja": "上野", "en": "Ueno" },
  "description": { "ja": "エリア全体の紹介と移動のポイント。", "en": "Area overview and travel advice." }
}
```

## 更新時の確認

- 施設の公式情報を確認し、ファイル先頭の `checkedAt` を確認日（`YYYY-MM-DD`）に更新します。
- 集合、見学、点呼、22:00以降の外出禁止に合わせて自由時間を計画します。掲載は訪問許可や公式行程への追加を意味しません。
- `npm run build` と `npm run test:sightseeing` で、形式・表示・フィルター・地図リンクを確認できます。
- 画面上の地図はOpenStreetMapの埋め込みです。APIキーや有料契約は不要です。地図・経路・外部サイトにはオンライン接続が必要ですが、初回のオフライン準備後は説明をオフラインで読めます。
- 地図の表記や操作ボタンは外部サービス側の言語設定に依存します。アプリ内の説明・メニューは日本語／英語の切り替えに対応しています。

初期データは2026年10月9日に、GO TOKYO、施設公式サイト、環境省、台東区の公式案内などを確認して作成しました。個々の情報源は各スポットの「情報の出典」から開けます。滞在時間はこのガイドの提案で、公式の所要時間ではありません。

## 経路の出発地を追加・変更する

同じJSONの `origins` 配列で出発地を管理できます。`name` は選択肢の表示名、`query` はGoogleマップに渡す施設名・住所です。現在は東京駅・品川駅・品川プリンスホテルを登録しています。

```json
{
  "id": "shinagawa-prince",
  "name": { "ja": "品川プリンスホテル", "en": "Shinagawa Prince Hotel" },
  "query": "Shinagawa Prince Hotel, 4-10-30 Takanawa, Minato City, Tokyo, Japan"
}
```

`origins` は少なくとも1件残してください。`id` は重複させず、同じ名前の別施設を避けるために住所も指定します。

表示テーマの初期値はライトモードです。利用者が明示的に選択・保存したライト／ダークの設定は、その後も保持されます。
